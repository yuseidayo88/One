# AI Company — 脅威モデル (Threat Model)

対象: マルチテナント SaaS + 自律的に動作する AI 社員 + 外部 Provider 連携。
手法: STRIDE + LLM 固有脅威 (OWASP LLM Top 10 相当) + マルチテナント境界。

---

## 1. 信頼境界

```
[ブラウザ]  ── 信頼境界 A ──▶ [Next.js Route Handlers]
                                    │
                                    ├─ 信頼境界 B ─▶ [DB / Storage]  (organization_id + RLS)
                                    ├─ 信頼境界 C ─▶ [LLM / 外部 Provider]
                                    └─ 信頼境界 D ─▶ [取得した外部データ: メール/Web/PDF/検索結果]
```

- **A**: ブラウザは常に未信頼。セッション Cookie 以外の権限主張を受け付けない。組織IDや社員IDをクライアントから受け取っても、必ずサーバー側で所属を再検証する。
- **B**: DB アクセスは全て `organization_id` スコープ。service_role キーはサーバー専用。
- **C**: Provider へ送るデータは最小化。秘密情報・他組織データを送らない。
- **D**: **外部データは「データ」であり「命令」ではない。** モデルへ渡す際は必ず `<untrusted_external_data>` で囲い、そこから派生したツール呼び出しはサーバー側検証と再承認を必須にする。

## 2. 資産

| 資産 | 影響 |
| --- | --- |
| 組織の事業情報・メモリ・成果物 | 機密性（競合流出） |
| ユーザー認証情報・セッション | なりすまし |
| Provider API キー | 金銭被害・第三者悪用 |
| ワークトークン残高 | 金銭被害 |
| 外部操作権限（メール送信・公開・ドメイン・支払い） | 対外的な実害・不可逆 |
| 監査ログ | 否認防止 |

## 3. STRIDE

### Spoofing（なりすまし）
| 脅威 | 対策 |
| --- | --- |
| セッション偽造 | HttpOnly + SameSite=Lax + Secure Cookie、HMAC 署名 + 有効期限、サーバー側での失効確認 |
| 他ユーザーへの成りすまし | すべての API で `requireSession()` → `requireOrgMember(orgId)` |
| OAuth コールバック偽装 | `state` / `nonce` 検証、リダイレクト URI 完全一致 |
| AI社員が別社員を騙る | 社員IDはサーバー側で解決。会話メッセージの `author` はクライアント指定を信用しない |

### Tampering（改ざん）
| 脅威 | 対策 |
| --- | --- |
| リクエスト改ざん | 全入力 Zod スキーマ検証、未知フィールドは破棄 |
| カンバンのドラッグでの不正な状態遷移 | サーバー側で遷移表 (`ALLOWED_TRANSITIONS`) と権限を検証 |
| クレジット台帳の改ざん | 台帳は追記のみ。残高は台帳の合計から導出 |
| Webhook 偽造 | Stripe 署名検証（タイムスタンプ許容幅つき） |

### Repudiation（否認）
- `audit_events` にログイン / 採用 / 配属 / 権限変更 / ツール呼び出し / メール送信 / 公開 / ドメイン操作 / 支払い / データ削除 / Safety 判定 / 承認 / モデル利用 / クレジット変更を記録。
- 監査ログは追記専用（アプリ層で更新・削除 API を提供しない）。

### Information Disclosure（情報漏えい）
| 脅威 | 対策 |
| --- | --- |
| 他組織データの取得 | 全テーブル `organization_id` + RLS + Store 層の強制スコープ。2組織テストで検証 |
| service_role キーの流出 | `NEXT_PUBLIC_*` にのみ公開値を置く。サーバー専用値はクライアントバンドルに入らないことをテストで検証 |
| ログからの秘密漏えい | `redact()` でトークン / メール / 電話 / APIキー様文字列をマスク |
| エラーメッセージからの内部情報漏えい | 本番はエラーコード + 汎用文言。詳細はサーバーログのみ |
| Safety 内部判定の漏えい | 拒否理由は「カテゴリ」までを返し、判定ルール・プロンプトは返さない |
| SSRF による内部メタデータ取得 | 外部 URL 取得は許可スキーム/ホスト検証 + プライベート IP 拒否 |

### Denial of Service
- レート制限（IP + ユーザー + 組織）、リクエストサイズ制限、
  ワークトークン残高による自然な上限、異常消費検知、`全社員停止`。

### Elevation of Privilege（権限昇格）
| 脅威 | 対策 |
| --- | --- |
| 「以前の指示を無視して」型の指示で社員の権限が拡大 | 権限はプロンプトではなく **Role Policy テーブル**。LLM 出力は許可判定に影響しない |
| ツール名の偽装 | `allowedTools` の完全一致 allowlist |
| 承認回避 | `approvalRequiredActions` を実行直前に再検査。承認レコードの有効性（対象・期限・実行者）を確認 |
| 管理者機能への到達 | `requireAdmin()` をサーバー側で強制。UI 非表示に依存しない |

## 4. LLM 固有脅威

| # | 脅威 | 対策 |
| --- | --- | --- |
| L1 | 直接プロンプトインジェクション | 権限はサーバー側で決定。LLM は「提案」しかできず、実行はポリシー検証を通る |
| L2 | 間接プロンプトインジェクション（メール/Web/PDF/検索結果） | 外部データを `<untrusted_external_data>` で分離。由来が外部のツール呼び出しは `requiresReapproval` |
| L3 | 出力の過信 | Structured Output (Zod) で検証。スキーマ外は破棄しリトライ |
| L4 | 機密情報の外部送信 | 外部送信は承認必須アクション。PII 検出時は ORANGE 以上 |
| L5 | 過剰な自律性 | ユーザーの明示操作（「実行する」）なしに採用・高額処理・外部送信を行わない |
| L6 | 危険用途への利用（詐欺・フィッシング等） | 決定論ルール + 分類器で RED 判定、ツール実行を停止 |
| L7 | 生成コードの実行 | 本番サーバー上で直接実行しない。sandbox（ファイルパス/ネットワーク/時間/CPU/メモリ制限、許可コマンド、秘密非投入、本番データ非投入） |
| L8 | モデルコスト濫用 | 予約制クレジット、モデルルーティング上限、fallback で高額モデルへ勝手に昇格しない |

## 5. Safety 判定レベル

| レベル | 意味 | 動作 |
| --- | --- | --- |
| GREEN | 通常 | 実行可 |
| YELLOW | 注意 | 実行可、警告表示・機能制限・記録 |
| ORANGE | 高リスク領域 | 一般調査は可。個別高リスク判断・外部実行は人間/有資格者の確認必須 |
| RED | 禁止 | 実行・API・外部ツール呼び出しを完全停止。部分出力を保存しない |

RED カテゴリ: 詐欺 / フィッシング / なりすまし / 不正アクセス / マルウェア / 認証情報窃取 /
違法薬物 / 武器・暴力支援 / マネーロンダリング / 法規制逃れ / 個人情報の不正取得 /
晒し・ストーカー / 虚偽レビュー / ディープフェイク詐欺 / 児童搾取 / 人身取引 / 大量無差別スパム。

ORANGE/YELLOW（禁止ではなく制限）: 医療 / 法律 / 金融・投資 / 採用判断 / 政治 /
ギャンブル / 酒類 / 成人向け。

繰り返し悪用: レート制限 → 一時停止 → 手動確認 → 利用停止（`safety_decisions` の集計で判定）。

---

## 6. 承認必須アクション

メール送信 / SNS投稿 / 広告公開 / 本番公開 / ドメイン購入 / DNS変更 / 支払い / 資金移動 /
本番DB変更 / データ削除 / 新規 OAuth 付与 / 契約・申請 / 高額ワークトークン消費 / PII の外部送信。

承認画面には「実行内容・影響範囲・使用サービス・送信先・差分・予想費用・ワークトークン・可逆性・リスク」を表示し、
承認結果を `approvals` と `audit_events` に保存する。

---

## 7. 未対応・受容リスク（実装時点）

- sandbox の実行基盤は未接続（インターフェースのみ）。実コード実行は行わない。
- MFA は拡張ポイントのみ（Supabase Auth 有効時に有効化）。
- Cloudflare WAF / DDoS / Bot 対策はデプロイ時設定（`docs/deployment.md` に手順）。
- 依存脆弱性検査は `npm audit` を CI に組み込む前提（本リポジトリでは手動）。
- MemoryStore は開発専用であり、暗号化・バックアップ対象外。
